# ADR-0784: Four common jobs keep a place of their own

Source of truth: this wiki page.

- **Area:** [§18 Jobs and Logs](ADR-Index.md#area-18)
- **Status:** Accepted
- **Version:** 3.1.0

**Decided.** Settings › Jobs has a Common jobs card after Current jobs, listing Fill gaps in every work, Fetch missing people, Fetch covers and details and Back up now in that order, the ones a reader runs most first. A reader gets the first two. The covers pass and the backup are an admin's, as their routes always were, and a row whose press could only be refused is left out rather than drawn disabled. Every row is always there. It says what the job does and how its last run ended, with its state, when and what it did, and that line opens the job's log in place. It offers Run, or Run again once the job has run in the thirty days Past jobs holds (a row with none says it has not run in them), and while the row's job runs or waits, the row says so and offers Stop instead. Run is `POST /jobs` with the row's params, so it is the same job any other screen starts, queued, stopped and kept like the rest; `GET /jobs/common` answers the rows this viewer may run, each with its last job and its current one. Two rows send params no other screen sends. A fill of `{all: true}` and a people fetch of `{missing: true}` are counted at the press, for the waiting row's total, and read what they walk only when they start: every book and then every film, show and game, or every record that lacks a provider's link or a stored portrait. Each logs how many it found. A fill of every work is not split at 2,000, since it is that job by name. What a record lacks is one function, `personLacks`, and the People console's pills and its Fetch missing read the same answer off `GET /people/records`. The covers row offers Run and Missing only. Its last run is the viewer's newest covers pass of either kind, wherever it was started (F14), and the backup row's is the server's newest backup, whoever made it. Back up now asks for the password first, in the Server card's own prompt. Each library row also says what it could still fill in, counted in the browser from the rows Metadata draws (`libraryGaps.js`). The fill counts the works it can find at a supplier (a work pinned by id, or a game with no id once IGDB can be asked, since the fill looks a game up there by its exact title) that have a field it writes still empty, and after that count, the works with such a gap it cannot find: "· 41 works need a source first". The people fetch counts what the People console's Fetch missing counts. The covers pass counts the books with no cover and the films with no poster whose supplier's record, kept from when they were added, names a TMDB poster (`poster_on_record`), because that is the only poster the pass fetches; a game from IGDB and a show from TheTVDB name none. When a count reaches none, the people row says "Nothing missing", and the fill and covers rows say "Nothing it can fill" and "Nothing it can fetch", because Metadata still flags works neither job can close. Those are a work with no source, which is Look up's job, and a low-res cover, which the covers pass's full Run replaces but its Missing only run, the one this count follows, does not. A first version said "Nothing missing" there, beside a Metadata badge of 41.

**Why.** My ask, *"add a list of common jobs, that can be restarted from there itself, and as such will have a persistent place"*. Before it each of the four lived on a screen of its own: the Server card, the Metadata page's header, a selection's bar and the People console. "When did I last do that, and did it work?" had no answer short of scrolling Past jobs, whose Run again offers only what the last thirty days kept. A job can wait its turn behind an hour's cover fetch, and a list taken at the press would leave out a work added meanwhile and ask again about a record that the People console's own Fetch completed meanwhile. With no list in the params, the same press twice is one job to the duplicate check, and Run again walks the library as it is by then.

**Instead of.** A Start a job panel listing every startable kind, which is a form for building params, not a row for the job a reader actually runs. The ids resolved at the press and sent as the job's params, which goes stale while the job waits and, for a library past 2,000 works, is more than one job's list may hold, so "every work" would become several jobs that each said so.
